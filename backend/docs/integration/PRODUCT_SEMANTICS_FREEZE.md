# Product semantics proposed for team freeze

1. `GET /api/v1/trends/skills` returns one snapshot's **observed skill ranking**. It has no scenario or learning pace input. Synthetic fixtures remain labelled `synthetic_demo`; null observed metrics are not growth statistics. Moderate/Fast only affect explicitly projected recommendation components under documented synthetic assumptions. No projected skill curve is exposed until a reviewed model and evidence exist.
2. `POST /api/v1/profiles/upload` is an additive proposed v1 endpoint. It reads PDF/DOCX bytes and extracts text, then reuses the existing profile normalization path. Upload does not confirm a skill. The default content-dependent rule fallback sets `meta.is_mock=true`; a real AI module is not currently connected. Demo CVs must be fictional. The declaration `synthetic_input=true` cannot detect hidden personal data, and this service is not ready for real personal CVs.
3. `activity_completed` and `skill_confirmed` are distinct conceptual progress events. The P1 `/progress/skills` endpoint returns 503 and stores neither event. No Bamboo segment is generated by opening a link or ticking a task. No login, plan adoption, cloud sync, or dynamic replanning API exists. The P0 roadmap response is generated advice, not a persisted cross-device plan. Any local UI progress display is a **Frontend Local Prototype**.

Team Lead and Frontend must confirm these semantics and the upload multipart contract before the API freeze.
